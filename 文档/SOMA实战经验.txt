SOMA 实战经验

本文件记录项目在实际落地过程中遇到的依赖、镜像、实验性/废弃 API 等问题及处理方案。
SOMA 架构规范本身保持相对稳定，本文件会随依赖版本、网络环境持续更新。

1. 仓库镜像配置

国内网络环境下，Android Gradle 插件和依赖下载经常超时或缺失。
经过对比，腾讯云镜像对新版 AndroidX（如 Navigation3 1.1.4）同步较快，推荐优先使用，官方源作为 fallback。

1.1 推荐配置

settings.gradle.kts：
    pluginManagement {
        repositories {
            maven { url = uri("https://mirrors.cloud.tencent.com/nexus/repository/gradle-plugin/") }
            maven { url = uri("https://mirrors.cloud.tencent.com/nexus/repository/maven-public/") }
            maven { url = uri("https://mirrors.cloud.tencent.com/nexus/repository/google/") }
            gradlePluginPortal()
            mavenCentral()
            google()
        }
    }
    dependencyResolutionManagement {
        repositoriesMode.set(RepositoriesMode.FAIL_ON_PROJECT_REPOS)
        repositories {
            maven { url = uri("https://mirrors.cloud.tencent.com/nexus/repository/google/") }
            maven { url = uri("https://mirrors.cloud.tencent.com/nexus/repository/maven-public/") }
            google()
            mavenCentral()
        }
    }

1.2 为什么选择腾讯云优先

- 阿里云 google 镜像对个别新版 AndroidX 包同步不完整，常见现象是 Gradle 能找到 metadata 却下载不到 aar/jar，最终报错。
- 腾讯云 google/maven-public 镜像在 Navigation3 1.1.4 上验证通过，可直接下载完整 artifact。
- 若腾讯云某包缺失或网络波动，Gradle 会自动回退到后续 google() / mavenCentral()。

1.3 Gradle 插件说明

Gradle 8.8+ 已内置 Foojay Toolchain Resolver，无需在 plugins { } 中声明 org.gradle.toolchains.foojay-resolver-convention，避免插件仓库访问问题。

2. 实验性 API 与废弃 API 处理

2.1 KoinStartup 实验性 API

KoinStartup / KoinInitializer 在 Koin 4.2.x 中仍标注 @KoinExperimentalAPI，编译时会产生 warning，不影响功能。

若项目要求零实验性 API，改用 Application.onCreate() 中手动 startKoin { }：
（1）移除 koin-androidx-startup 工件依赖，仅保留 koin-android。
（2）Application 类不再实现 KoinStartup 接口：
    class TemplateApplication : Application() {
        override fun onCreate() {
            super.onCreate()
            startKoin {
                androidLogger()
                androidContext(this@TemplateApplication)
                modules(appModule)
            }
        }
    }
所需 import：
    import org.koin.android.ext.koin.androidContext
    import org.koin.android.ext.koin.androidLogger
    import org.koin.core.context.startKoin
注：此方案失去 AndroidX App Startup 自动启动优势，Koin 在 Application.onCreate() 中同步启动。

2.2 WindowWidthSizeClass 弃用处理

androidx.window.core.layout.WindowWidthSizeClass 自 window 1.4.0 起标记 @Deprecated，官方推荐改用 WindowSizeClass。

处理方案：
（1）CompositionLocal 三件套改为提供 WindowSizeClass 类型：
    val LocalWindowSizeClass = compositionLocalOf<WindowSizeClass> {
        error("WindowSizeClass not provided")
    }
    @Composable
    fun ProvideWindowSizeClass(content: @Composable () -> Unit) {
        val windowSizeClass = currentWindowAdaptiveInfo().windowSizeClass
        CompositionLocalProvider(LocalWindowSizeClass provides windowSizeClass) { content() }
    }
    @Composable
    fun rememberWindowSizeClass(): WindowSizeClass = LocalWindowSizeClass.current
（2）分发判断改用 isWidthAtLeastBreakpoint：
    val windowSizeClass = rememberWindowSizeClass()
    val isLandscape = windowSizeClass.isWidthAtLeastBreakpoint(WindowSizeClass.WIDTH_DP_MEDIUM_LOWER_BOUND)
（3）所需 import：
    import androidx.window.core.layout.WindowSizeClass

断点常量含义：
- WIDTH_DP_MEDIUM_LOWER_BOUND = 600dp
- WIDTH_DP_EXPANDED_LOWER_BOUND = 840dp
原 COMPACT/MEDIUM/EXPANDED 三档语义改由 isWidthAtLeastBreakpoint/isAtLeastBreakpoint 表达：
- COMPACT：!isWidthAtLeastBreakpoint(600)
- MEDIUM：isWidthAtLeastBreakpoint(600) && !isWidthAtLeastBreakpoint(840)
- EXPANDED：isWidthAtLeastBreakpoint(840)
